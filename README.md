# 🎤 מי הזמר — משחק ניחושים מוזיקלי

משחק קבוצתי בזמן אמת: המשתתפים רואים שם של שיר עברי מפורסם ושנת
היציאה שלו, ובוחרים מתוך ארבע אפשרויות מי ביצע אותו **במקור** — לא
תמיד מי שהפך אותו ללהיט. ניקוד לפי נכונות ומהירות, טבלת דירוג בין
סיבובים, ופודיום בסיום.

המנהל פותח משחק ומקרין את הקוד; המשתתפים סורקים QR מהטלפון ומצטרפים
תוך שניות, בלי התקנה ובלי הרשמה. אין נגן שירים ואין מילות שיר —
המשחק כולו טקסטואלי, על טריוויה של זהות המבצע.

## מה יש במשחק

### מסך המנהל

| יכולת | פירוט |
| --- | --- |
| יצירת משחק | בחירת דרגת קושי ומספר שאלות (5/10/15/20, ברירת מחדל 10), קוד ייחודי בן 5 תווים, קישור הצטרפות ו-QR — נוצרים מיד |
| לובי חי | רשימת המשתתפים ומספרם מתעדכנים בזמן אמת |
| שליטה מלאה | התחלה, עצירה זמנית וחידוש מדויק, דילוג לשיר הבא, סיום מוקדם, פתיחת סיבוב חדש באותו חדר |
| מסך משחק | שם השיר, שנת היציאה, מספר הסיבוב, טיימר, מד "כמה כבר ענו" |
| חשיפה בין סיבובים | המבצע/ת המקורי/ת נחשף/ת מיד בתום כל סיבוב, יחד עם טבלת דירוג מעודכנת |
| סיכום | טבלת דירוג מלאה ופודיום עם קונפטי |

### חוויית המשתתף

1. סריקת QR או כניסה לקישור.
2. הזנת שם ולחיצה על "הצטרפות למשחק".
3. מסך המתנה עד שהמנהל מתחיל.
4. בכל סיבוב: שם השיר ושנתו, וארבע כרטיסיות עם שמות מבצעים אפשריים.
   ניתן לשנות את הבחירה עד תום הזמן — אחריה היא ננעלת.
5. מיד בתום הסיבוב: מי המבצע/ת המקורי/ת באמת, האם צדקתי וכמה נקודות קיבלתי.
6. בסיום: דירוג אישי, טבלת דירוג מלאה ופודיום.

### מה **לא** נחשף במהלך סיבוב פעיל

זו דרישת יסוד של המשחק, והיא נאכפת בשרת ולא רק בממשק: המבצע/ת
המקורי/ת ותשובות שחקנים אחרים **אינם נשלחים כלל לדפדפן** לפני שהסיבוב
נסגר. מה שכן מוצג בזמן אמת: ניקוד מצטבר, מספר הסיבוב, הטיימר וכמה
שחקנים כבר ענו (בלי לגלות מה ענו).

## הפעלה מהירה

דרישה מוקדמת: **Node.js 20.11 ומעלה**.

```bash
npm install          # התקנת כל חבילות ה-workspace
npm run build        # בניית shared → client → server
npm start            # השרת מגיש גם את הלקוח, בכתובת http://localhost:3000
```

### פיתוח

```bash
npm run dev          # שרת (3000) + Vite עם HMR (5173) במקביל
```

בפיתוח יש להיכנס ל-<http://localhost:5173>. בקשות ה-WebSocket מנותבות
אוטומטית לשרת, כך שההתנהגות זהה לייצור.

> **לשחק מהטלפון בזמן פיתוח:** שרת ה-Vite מאזין לכל הכתובות ברשת
> המקומית. היכנסו מהמחשב לכתובת ה-IP של המחשב ברשת (למשל
> `http://192.168.1.20:5173`) — ה-QR ייווצר עם אותה כתובת ויעבוד מהטלפון.

### עקרונות מנחים

**השרת הוא מקור האמת היחיד.**
הזמן, סדר השירים, המבצע המקורי והניקוד נמצאים בשרת בלבד. הלקוח
מציג — ולא מחשב. כך אין רמאות ואין מצב שבו שני מסכים מראים דברים
שונים.

**לוגיקה משותפת נכתבת פעם אחת.**
נוסחת הניקוד ובניית הדירוג יושבות ב-`shared` ורצות בדיוק אותו הדבר
בשני הצדדים. השרת מחשב את הניקוד; הלקוח משתמש באותם טיפוסים לתצוגה.

**מנוע המשחק אינו מכיר רשת.**
`GameRoom` לא יודע דבר על Socket.IO — הוא מדווח על שינויים דרך
callbacks ומקבל `Scheduler` בהזרקה. לכן הוא נבדק במלואו עם שעון
מדומה, בלי לפתוח אף חיבור.

**זמן מסונכרן, לא זמן מקומי.**
כל טיימר מבוסס על חותמות זמן של השרת. הלקוח מודד את הפרש
השעונים בשיטת Cristian עם מספר דגימות, כך שגם מכשיר עם שעון
שגוי מציג את אותה שנייה כמו כולם.

**RTL מלא, לא תוספת.**
כל ה-CSS משתמש במאפיינים לוגיים (`inline-start`/`inline-end`),
ולכן העברית עובדת נכון והוספת שפה נוספת אינה דורשת שכתוב.

### זרימת המשחק

```
lobby ──start──▶ countdown ──▶ question ──┬──▶ reveal ──▶ question …
  ▲                  │            │       │
  │                pause/resume ◀─┘       └── (שיר אחרון) ──▶ finished
  └──────────────── restart ─────────────────────────────────────┘
```

בשונה ממשחקים שמסתירים תוצאות עד הסוף, כאן **כל סיבוב נחשף מיד**
(שלב `reveal`) — כך שהדירוג מתעדכן לעיני כולם לאורך המשחק ולא רק
בסופו, בדיוק כמו במשחקי טריוויה חיים.

חיבור מחדש נתמך בכל שלב: לכל שחקן וגם למנהל יש אסימון סודי הנשמר
מקומית, ורענון דף או נפילת רשת מחזירים אותו לאותו מקום עם אותו ניקוד.

## מנגנון הניקוד

הניקוד תלוי בנכונות ובמהירות:

```
points(correct, t) = correct ? round(400 + 600 · (1 − t/T)) : 0
```

כאשר `t` הוא הזמן שחלף עד התשובה ו-`T` משך הסיבוב. תשובה נכונה
ומיידית שווה כ-1000 נקודות; תשובה נכונה ברגע האחרון עדיין שווה
400; תשובה שגויה או שלא נענתה שווה תמיד 0. תשובה נכונה איטית
מנצחת תמיד תשובה שגויה מהירה.

**דרגת הקושי אינה משפיעה על הניקוד** — היא קובעת רק מאיזה מאגר
נשלפים השירים (ראו למטה). ניקוד זהה לכל השחקנים, בכל דרגת קושי.

שוברי שוויון בדירוג הסופי: ניקוד מצטבר גבוה יותר, ואז מספר תשובות
נכונות, ואז לפי שם.

## מאגר השירים

השירים מאורגנים בקובץ מובנה אחד, `shared/src/content/songs/hebrew-classics.ts`,
כאובייקטים פשוטים — קל להוסיף עוד שירים בלי לגעת בשום קוד אחר (ראו
[הרחבת המשחק](#הרחבת-המשחק)).

כל שיר כולל: שם, מבצע/ת מקורי/ת, שנה, דרגת קושי, ושלוש הסחות דעת
(מבצעים סבירים אחרים). שירים שבהם קיים ספק סביר — למשל שיר שזוהה
עם גרסת כיסוי מאוחרת ומפורסמת יותר מהמקור — מסומנים בשדה `note`
עם ההסבר והמקור, כדי שיהיה קל לאמת או לתקן.

**המאגר הנוכחי: 61 שירים** — 31 בדרגת קל, 21 בבינוני, 9 במקצוענים.
כל שיר אומת מול מקור חיצוני, שיר-שיר (לא מרשימות-כיסויים מרוכזות,
שנוטות להחזיר מידע לא אמין). דרגת מקצוענים קטנה משמעותית מהאחרות
בכוונה: כל שיר בה דורש שרשרת כיסויים מתועדת ואמיתית, ולא כל שיר
"ותיק" מתאים — העדפנו רשימה קטנה ומדויקת על פני ניחושים כדי למלא
מכסה. הרחבת דרגת המקצוענים בפרט היא היעד הטבעי הבא.

דוגמאות ל"מלכודות" שתועדו במפורש בשדה `note`:

- **"ירושלים של זהב"** — נעמי שמר כתבה והלחינה, אך שולי נתן הייתה
  המבצעת המקורית (1967).
- **"בדד"** — שרשרת כיסויים מתועדת מ-1961, שהגרסה המפורסמת ביותר
  שלה (זוהר ארגוב, 1982) היא הרביעית בשרשרת.
- **"חלומות"** — רוחמה רז ביצעה במקור ב-1979; אייל גולן הפך אותו
  ללהיט ענק בכיסוי מ-2003.
- **"קפה אצל ברטה"** — יגאל בשן הוא המבצע המקורי (1974), חרף
  יותר מ-130 ביצועים מתועדים אחרים לשיר.
- **"את לי לילה"** — בועז שרעבי כתב, הלחין וביצע במקור (1978); זוהר
  ארגוב הקליט כיסוי ב-1981 שהפך לגרסה המזוהה עם השיר.
- **"גלבי"** — שיר תימני של אהרן עמרם; עופרה חזה למדה אותו ישירות
  ממנו והקליטה גרסה (1984) שהפכה ללהיט בינלאומי המזוהה כמעט אך ורק
  איתה (שנת ביצועו המקורי של עמרם אינה מתועדת במדויק — סומנה כספק).

## תצורה

כל ההגדרות דרך משתני סביבה, עם ערכי ברירת מחדל שמתאימים להרצה מקומית.

| משתנה | ברירת מחדל | תיאור |
| --- | --- | --- |
| `PORT` | `3000` | פורט ההאזנה |
| `HOST` | `0.0.0.0` | כתובת ההאזנה |
| `PUBLIC_BASE_URL` | *(נגזר מהבקשה)* | כתובת ציבורית לבניית קישור ה-QR. הכרחי מאחורי פרוקסי שמשנה מארח |
| `CORS_ORIGINS` | `*` | מקורות מותרים, מופרדים בפסיק |
| `ROOM_TTL_MINUTES` | `240` | משך חוסר פעילות שאחריו חדר נטוש נסגר |
| `MAX_ROOMS` | `500` | תקרת חדרים פעילים בתהליך |
| `SERVE_CLIENT` | `true` | האם להגיש את קבצי הלקוח הבנויים |
| `CLIENT_DIR` | `client/dist` | נתיב לתיקיית הלקוח |
| `TRUST_PROXY` | `true` | כיבוד כותרות `X-Forwarded-*` |
| `LOG_LEVEL` | `info` | `debug` / `info` / `warn` / `error` |

ראו `.env.example`.

### Render

הרפוזיטורי מוכן לפריסה ב-Render ללא הגדרות ידניות, דרך ה-Blueprint
בקובץ `render.yaml` שמפנה ל-`Dockerfile` הקיים ומגדיר בדיקת תקינות
מול `/healthz`.

1. ב-[Render Dashboard](https://dashboard.render.com), **New → Blueprint**,
   וחברו את הרפוזיטורי `mi-hazamar`.
2. Render מזהה את `render.yaml` ומציע ליצור את השירות — אשרו (Apply).
3. אחרי שהבנייה מסתיימת, השירות עולה עם כתובת מסוג
   `https://mi-hazamar.onrender.com` (או דומה) — ה-QR וקישור ההצטרפות
   נבנים ממנה אוטומטית, בלי הגדרה ידנית.

**למה אין צורך להגדיר `PUBLIC_BASE_URL`:** Render מזריק את
`RENDER_EXTERNAL_URL` לסביבת הריצה, והשרת בונה ממנו את כתובת הבסיס
אוטומטית (ר' `server/src/config.ts`). זו ההגדרה הקריטית ביותר
בפריסה — ממנה נבנה קוד ה-QR, וכתובת שגויה שוברת את המשחק בשקט
מוחלט. אם אתם מחברים דומיין משלכם, הגדירו
`PUBLIC_BASE_URL=https://your-domain.com` והיא תגבר.

### Railway

הרפוזיטורי מוכן גם לפריסה ב-Railway, דרך `railway.json` שמפנה
לאותו `Dockerfile`.

1. **New Project → Deploy from GitHub repo**, ובחרו את הרפוזיטורי.
2. **Settings → Networking → Generate Domain**. זהו — אין מה להגדיר עוד.

Railway מזריק את `RAILWAY_PUBLIC_DOMAIN` ואת `PORT` אוטומטית, באותה
רוח בדיוק כמו Render.

## הרחבת המשחק

להוספת שיר: פתחו את `shared/src/content/songs/hebrew-classics.ts`
והוסיפו אובייקט `Song` חדש למערך המתאים לדרגת הקושי — `id` ייחודי,
`title`, `originalArtist`, `year`, `difficulty`, ומערך `distractors`
בן שלושה מבצעים סבירים אחרים (רצוי מאותה תקופה, או שביצעו כיסוי
לאותו שיר). אם יש ספק סביר לגבי זהות המבצע המקורי — הוסיפו `note`
עם ההסבר והמקור. הבדיקות ב-`hebrew-classics.test.ts` יוודאו שהרשומה
תקינה מבנית (מזהה ייחודי, שלוש הסחות דעת שאינן זהות למבצע האמיתי).

להוספת חבילת שירים חדשה לגמרי (למשל ז'אנר אחר): צרו קובץ נוסף
לצד `hebrew-classics.ts`, ורשמו אותו ב-`SONG_PACKS` שב-
`shared/src/content/songs/index.ts`.
